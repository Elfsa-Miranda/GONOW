# P09-005 Candidate UI lazy-list diagnostic closure

- Scope: `TASK-P09-005`; local provisional validation only; production writes `0`.
- Reproduction: the first widget run passed model and analyzer checks, but seven assertions below the initial `ListView` viewport could not find nodes. A semantic finder then failed as a pre-materialization scroll target. Stable physical keys materialized the evidence node, after which a separate `bySemanticsLabel` traversal still reported zero matches. Direct node inspection finally showed the required label followed by merged `ListTile` text.
- Root cause and impact: `ListView` lazily materializes children while the tests treated offscreen nodes as already present. Flutter's `scrollUntilVisible` works on an element finder, a wrapping `Semantics` node merges useful descendant text, and `CheckboxListTile` creates its own child semantics boundary. The fixture incorrectly treated physical lookup, wrapper semantics, and child-control semantics as one exact value. Once those assertions passed, Flutter 3.41.7 also showed that `addTearDown` runs too late for the framework's active-handle end check. Production decision logic did not fail; the impact remained the accessibility fixture lifecycle.
- Reversible repair: retain the lazy list and useful descendant semantics, add stable non-sensitive keys to the evidence/warning wrappers and conflict wrapper, keep the existing child-control key for interaction, scroll by wrapper key, inspect the actual materialized `SemanticsNode` for the required label fragment, and dispose the test-only semantics handle in `finally`. No threshold, skip, business adapter, identity, prompt, or data contract changed.
- Affected regression: the minimum accessibility reproduction passed, followed by all nine Candidate fixtures, targeted analyzer, WorksetVerify, Verify, Security, Evidence, and RollbackVerify. Final local counts were failures/skips/analyzer issues/unapproved business writes/security findings/unexpected paths `0`; the runner retains `recovered_diagnostic_failure_count=6`.
- Rollback: remove the keys and their test anchors together. The feature flag remains off and no formal write is enabled. The escalation and recovery conditions are tracked in `BLK-P09-002`.
